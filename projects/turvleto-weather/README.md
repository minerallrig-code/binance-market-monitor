# Turvleto Weather — погодный пост для «ТУР В ЛЕТО»

Автоматическая публикация погоды по пяти направлениям Вьетнама в Telegram:
один пост — фото-карточка со всей информацией, без текста.

- Города: Нячанг, Муйне, Фукуок, Дананг, Далат.
- Данные: [Open-Meteo Forecast API](https://api.open-meteo.com/v1/forecast), без ручных значений.
- Периодичность: раз в три дня, ориентировочно 08:00 по Вьетнаму (UTC+7).
- Только текст и карточка. Видео, изображения с камер и диагностика в тему не отправляются.

## Расписание

Workflow `.github/workflows/turvleto-daily-weather.yml`:

- cron `0 1 * * *` — ежедневная проверка в 01:00 UTC;
- шаг календаря решает, публиковать ли сегодня: `(сегодня − опорная дата) % интервал == 0`;
- опорная дата и интервал заданы в `env` workflow: `TURVLETO_ANCHOR_DATE` (`2026-11-11`) и `TURVLETO_CYCLE_DAYS` (`3`). Чтобы изменить график, достаточно поменять эти значения — код править не нужно;
- расчёт идёт по дате Вьетнама, а не UTC;
- в промежуточные дни workflow стартует, печатает `publish=false` с датой и причиной, затем пропускает установку зависимостей и публикацию;
- `workflow_dispatch` обходит календарь и публикует сразу — для теста или внепланового поста.

Календарь от опорной даты: 11, 14, 17, 20, 23 ноября и далее каждые три дня.

### Про время запуска

Планировщик GitHub не гарантирует запуск в минуту. По наблюдениям с 9 по 15 ноября плановые запуски этого репозитория стартовали на **6–7 часов позже** слота (около 14:30–15:10 по Вьетнаму вместо 08:00); вероятная причина — два workflow с расписанием `*/15` в этом же репозитории. Если время публикации критично, проверяйте его по самой теме Telegram, а не по cron.

## Локальный запуск

```bash
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN=...      # секрет, не коммитить
export TELEGRAM_CHAT_ID=-1003065943939
export TELEGRAM_MESSAGE_THREAD_ID=114
python weather_post.py
```

Без переменных окружения скрипт дойдёт до отправки и упадёт на её отсутствии — это ожидаемо.

## Поведение при ошибках

- Запрос Open-Meteo: три попытки с паузами 2 и 4 с. Повторяются сетевые сбои и ответы 5xx; ответ 4xx не повторяется — он означает ошибку в запросе, а не сбой.
- Обязательные поля проверяются отдельно: вместо `KeyError` в лог попадает сообщение вида `НЯЧАНГ: field current.apparent_temperature is null`. Вероятность дождя, влажность и ветер считаются необязательными — если их нет, в посте будет «дождь —», а публикация не блокируется.
- Если хотя бы один город не получен — **пост не публикуется**, ошибки остаются в логе Actions. Неполный прогноз не выдаётся за полный.
- Если карточка не отрисовалась — уходит текстовый пост.
- Если Telegram не принял фото — уходит текстовый пост, причина в логе.
- Подпись к фото не отправляется: вся информация на карточке, пост состоит из одного сообщения. Если подпись понадобится (например, для хештегов, которые работают только в тексте), задайте её в `PHOTO_CAPTION` в `weather_post.py` — лимит 1024 символа.

## Как проверить, что пост ушёл

Общий статус workflow `success` сам по себе ничего не значит. Смотрите шаги:

1. `Report publishing decision` — `publish=true/false`, дата и число дней от опорной даты;
2. `Publish weather for five destinations` — выполнился ли шаг;
3. в логе публикации — строка `Weather card sent; message_id = ...`;
4. и уже затем — саму тему 114 в Telegram.

Артефакт `turvleto-weather-card` хранит отправленную карточку 3 дня.
